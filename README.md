# Агент деканата

Система для работы с данными деканата: FastAPI и PostgreSQL со всеми56 исходными и16 служебными таблицами, React-интерфейс с пятью ролями, формы и шесть операций с приказами, 13 режимовOLAP, серверные чаты/SSE, очередь согласования, OCR PDF и поиск по опубликованным нормативам. Агент использует14 ограниченных инструментов: он готовит проверяемые предложения, а изменения применяются только после отдельного решения уполномоченного пользователя. Права, предметные правила, транзакции и аудит проверяются на сервере.

Разработка велась с помощью Codex; в ранних испытаниях агент работал с Qwen2.5-7B-Instruct, а итоговый локальный профиль использует Qwen3.5-9B Q4_K_M через LM Studio0.4.26 с контекстом20480, parallel1, temperature0.6 и ответом до1536 токенов. Для нормативного поиска используется BAAI/BGE-M3 с dense/sparse индексом Qdrant1.15.5. Проект проверялся на Windows11 Enterprise, Docker Desktop с Linux-контейнерами, Python3.13.1 и Node.js22.14.0 на ноутбуке с16 ГБ RAM и NVIDIA RTX4060 Laptop8 ГБ; использовались настоящие PostgreSQL17, LM Studio/CUDA12, BGE и Tesseract5 с русским и английским языками. В предыдущей версии12.10.2026 автоматические проверки, native-вызовы модели и видимый браузерный проход109 случаев охватили все пять ролей и13 функций агента; отдельные сбои и ограничения сохранены в [матрице проверок](docs/VISIBLE_BROWSER_QA.md), а не заменены общим утверждением о готовности.

Точная копия базы сначала прошла restore и миграции; контрольный backup новой схемы также проверен. [Результат развёртывания](docs/qa/live-upgrade-20261015-results.json). Исходники фронтенда коллеги сохранены.

Повторная [проверка после перехода на новую БД](docs/qa/FULL_VERIFICATION_20261015.md):489 passed,7 явных skipped и372 успешных subtests, отдельно12 Linux parser/OCR и2 реальные гонки. ## Главные решения

Один backend FastAPI, существующий корневой агент DeepAgents внутри него, PostgreSQL со всей схемой `deanery`, Qdrant и BGE-M3 для нормативного поиска. Отдельный worker обрабатывает файлы, индексирует документы и применяет наступившие приказы. Авторизация и ответы API соответствуют клиенту, включая access token в памяти браузера и refresh cookie.

Форма сохраняет запись сразу после нажатия предусмотренной кнопки. Агент сначала готовит предложение; сотрудник принимает решение в существующем окне «было → стало». Обе ветки используют одинаковые серверные права, правила БД, транзакции и аудит. Нельзя заменить ответ формы предложением: нынешний фронтенд ожидает уже сохранённую запись.

Четыре выбранные функции реализованы в рабочем React и API: серверная очередь, передача предложения сотруднику, отдельные состояния решения/исполнения и manifest вложений. Снимок исходного frontend и HTML-макет сохранены для сравнения.

Полный OLAP, серверные чаты и восстановление SSE, назначение/прекращение/отмена будущей стипендии, коррекция закрытой оценки, OCR всех страниц принятого PDF и отмена неисполненного приказа включены и реализованы. Прежние восемь режимов OLAP и пять новых используют утверждённые показатели и серверную область пользователя. Последние предметные решения подтверждены: root-контакты меняет только admin; новое назначение стипендии начинается сегодня или позже.

**Функциональный объём окончательно зафиксирован пользователем:** существующие возможности и все согласованные дополнения реализованы; остальные расширения исключены. Главный документ — [подробный план](docs/DETAILED_IMPLEMENTATION_PLAN.md). Последние предметные вопросы закрыты; технические решения записаны в журнал по разрешению пользователя.

## Материалы

Источник интерфейса: `Lyaako/dean-agent-front`, ветка `react-frontend`, commit `9c68ae0c5f062b87811058599151bc135576b33d`. Источник логики агента: корневой `dean_agent` из `Ethenkam/dean-agent`, commit `d92bf5fbfc5b37c3236a6454aeffa5374fe88b11`. Снимки нужных исходников сохранены в `references/frontend-source` и `references/agent-source` только для анализа. Прежний `backend_dean` не использовался как источник кода; этот репозиторий теперь содержит собранную работу.

В `references/database` сохранены исходные SQL и документация из вложений. В них 56 таблиц, 312 столбцов, 83 внешние связи и 27 представлений. Структура сохранена целиком; наличие таблицы не означает разрешение свободно изменять её через HTTP или модель.

Макет использует синтетические данные и собственные заглушки автора фронтенда. Он не демонстрирует работу реального ИИ/backend. Рядом с `index.html` должны оставаться `styles.css`, `app.css`, `extra.css`, `icons.js`, `data.js`, `ui.js`, `app.js`, `chat.js` и `logo.svg`; для некоторых шрифтов и просмотра вложений исходный макет обращается к CDN. Его экран входа принимает любые непустые демонстрационные логин/пароль. Исходные SQL пересоздают схему и содержат демонстрационные настройки: production-миграции должны быть отдельными.
