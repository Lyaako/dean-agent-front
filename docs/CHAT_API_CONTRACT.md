# Серверные чаты: контракт для прямого согласования

Статус: контракт P00 прямо подтверждён пользователем ответом «Подтверждаю контракт чатов». Серверное хранение, физическое удаление переписки, сохранение предложений/аудита и запрет удаления активного run до явной остановки также подтверждены. Здесь не выбираются сроки хранения файлов и служебных данных.

Пути под существующим /api/v1. Владелец определяется по Bearer; user_id и роль не принимаются из тела. Все роли работают только со своими чатами. Недоступный/удалённый чат не раскрывает чужие данные.

## Маршруты

| Метод и путь | Тело/параметры | Результат |
|---|---|---|
| GET /agent/sessions | limit 1..500, offset >=0 | {items: ChatSummary[], limit, offset, has_more}; updatedAt по убыванию, стабильный порядок по id |
| POST /agent/sessions | {title}; Idempotency-Key одной попытки создания | 201 с SessionInfo; сервер создаёт принадлежащую пользователю беседу и её UUID |
| GET /agent/sessions/{id} | — | SessionInfo |
| GET /agent/sessions/{id}/messages | limit 1..500, offset >=0 | {items: ChatMessage[], limit, offset, has_more}; порядок сообщений серверный, по времени и стабильному порядковому номеру |
| PATCH /agent/sessions/{id} | {title} | Обновлённый SessionInfo |
| DELETE /agent/sessions/{id} | — | 204 после физического удаления переписки; 409 session_busy, пока run активен/останавливается |

Названия после удаления пробелов по краям — непустые, до 255 символов. Эта граница подтверждена вместе с контрактом. Автоматический заголовок первой отправки сохраняет существующую titleFrom (до 60 символов).

ChatSummary сохраняет имена текущего ChatStore: {id, title, updatedAt, preview}. Preview — до 120 символов последнего неошибочного сообщения, как в исходном localChatStore.

SessionInfo: {id, title, sessionId, createdAt, updatedAt, activeRunId}. Id и sessionId — один серверный UUID; activeRunId — UUID текущего запуска или null; даты — ISO 8601 с зоной. Полная история получается отдельным запросом messages с пагинацией.

ChatMessage сохраняет существующие поля: {id, role: user|agent|error, text, at, attachments?, proposals?, tools?, requestId?, decisions?}. Вложения содержат metadata разрешённой версии, предложения/решения отражают актуальное состояние сервера. Неавторизованные поля/файлы не возвращаются. Внутренние SQL/секреты/полный приватный trace в сообщения не добавляются.

## Работа существующего интерфейса

- «Новый чат» оставляет пустой локальный экран, как сейчас. Перед первой отправкой клиент создаёт серверную беседу, затем передаёт её session_id в POST /agent/chat/stream. Повтор создания с тем же ключом не создаёт второй чат.
- Пользовательское сообщение и результат агента сохраняет backend в рамках запуска. Клиент не загружает весь Chat вместе с messages обратно через save: локальный объект нужен для отображения текущего ответа, а сервер является источником истории.
- Серверный адаптер ChatStore получает список и полную сохранённую историю страницами, без прежнего скрытого удаления старых сообщений при превышении 300 и чатов при превышении 50. Будущая очистка по срокам требует отдельного согласования.
- Переименование меняет только title, не тела сообщений. Изменения из другого устройства получаются при повторном чтении серверных данных.
- «Удалить» физически удаляет переписку и исключает чат из списка. Предложения и предметный аудит сохраняются; их связь не требует сохранения архива переписки. Удаление не запускает каскадное удаление предложений/аудита.
- Пока агент работает/останавливается, удаление отказывает. Клиент показывает подтверждённое сообщение «Сначала остановите агента». Пользователь явно останавливает его по SSE_API_CONTRACT.md, после завершения остановки повторяет удаление.
- Собственные черновики/список вложений до отправки остаются текущим состоянием интерфейса; их новая синхронизация между устройствами этим контрактом не добавляется. Импорт старого localStorage исключён ранее.

Пользователь отдельно подтвердил конкурентное переименование: сохраняется последнее успешно записанное сервером название. Другие устройства получают его при следующем чтении.

Для физического удаления также прямо подтверждено: удалять сообщения, очищать копии текстов/ответов в agent_run JSONB и сохранённых результатах повторной отправки; deanery.agent_request.request_text заменяется меткой «Переписка удалена», response_text очищается. Служебные сведения запуска, предложения и официальный аудит сохраняются; загруженные файлы имеют отдельные правила хранения. Не сохранять переписку как скрытый архив в событиях/кэше.

Отдельно подтверждено отсутствие автоматической очистки по возрасту для файлов, событий, служебных записей, предложений и аудита. Это не отменяет явную очистку копий удалённой переписки.
