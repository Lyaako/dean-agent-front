# Реализованная основа БД P01

Текущий head —0039_scope_check_latency,71 прикладная таблица. API и весь план реализованы; ниже сохранено описание первоначального P01. Последние forward-миграции0038 фиксируют подтверждённые правила контактов/стипендий,0039 отключает JIT только в живой проверке области доступа. Таблицы, владельцы, grants и последовательности сохранены; исходные184 SQL checks прошли. Полная приёмка: [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md).

## Структура

- [bootstrap.sql](../backend/db/bootstrap.sql) создаёт технические роли и закрывает публичный CREATE. Его выполняет администратор новой среды, до миграций.
- [alembic.ini](../alembic.ini) и [env.py](../backend/db/migrations/env.py) применяют версии в одной транзакции с SET LOCAL ROLE backend_migration.
- [0001_deanery](../backend/db/migrations/versions/0001_deanery.py) создаёт исходную схему, представления/процедуры/триггеры и группы исходных прав. Удаление схемы и демонстрационный пароль исключены.
- [0002_agent_backend](../backend/db/migrations/versions/0002_agent_backend.py) создаёт 15 утверждённых сущностей, индексы и ограничения хранения. [SQL служебной схемы](../backend/db/migrations/sql/004_agent_backend.sql).
- [0003_storage_checks](../backend/db/migrations/versions/0003_storage_checks.py) закрывает обход проверок состояния через SQL/JSON null.
- [test_database.py](../backend/tests/test_database.py) проверяет настоящую PostgreSQL. [verify.py](../backend/db/verify.py) выполняет Python-проверки и исходные SQL-тесты на подготовленной тестовой БД.

В одной БД: deanery —56 таблиц; agent_backend —15; public.alembic_version —одна. Всего71 прикладная или72 с технической таблицей. backend_api содержит защищённые функции API, операций и отдельных worker; рабочие подключения не получают прямую запись в предметные таблицы.

События SSE находятся в agent_run.events JSONB. Новых таблиц событий, ролей приложения, очереди, OCR-страниц или OLAP-агрегатов не создано. Извлечение/manifest сохраняются в утверждённых JSONB структурах. Общие TTL, бюджеты и нерешённые правила функций не заданы схемой молча.

## Воспроизведение

Требование исходного SQL — PostgreSQL 14+ и btree_gist. В проверке использован уже установленный PostgreSQL 17. Создан отдельный контейнер dean-plan-p01-postgres с доступом только через 127.0.0.1; его текущий порт — 51359. Существующие контейнеры и БД не затронуты.

В новой пустой среде администратор выполняет bootstrap.sql. Переменная DATABASE_URL задаёт SQLAlchemy URL с драйвером postgresql+psycopg; пользователь соединения должен иметь право переключиться на backend_migration. Затем из корня проекта:

```powershell
python -m alembic upgrade head
```

Первое развёртывание создаёт схему, повторное выполняет только ещё не применённые версии. Существующая deanery без миграционной истории не сбрасывается: такой конфликт требует отдельного согласованного переноса. Destructive downgrade не реализован.

03_seed.sql **не входит в миграции**. Он загружается отдельно и только в тестовую БД; содержит вымышленные данные и демонстрационные учётные записи. API/worker не должны соединяться как postgres или backend_migration. Рабочие роли пока NOLOGIN, без доступа к исходным данным; выдача рабочих разрешений и protected scope относится к P02.

Частные подключения текущей проверки сохранены в игнорируемой .local, без паролей в документации. Для проверки тестовой копии:

```powershell
python -m backend.db.verify .local/p01-repro-connection.json
```

Этот запуск требует подготовленных миграций и исходного тестового seed; его не запускают на рабочей БД. Исполняются исходные SQL-команды, служебные psql-строки echo удаляются адаптером. Тестовые строки откатываются; identity/sequence могут оставлять пропуски.

## Полученные результаты и границы

Прошли 32 Python-проверки, включая 10 integration, и 184 исходные SQL-проверки. Проверены все исходные поля/типы/nullable/identity/PK, количество FK и имена views; запрет глобального чтения и DDL рабочих ролей; неизменяемость команд/файлов; удаление копий беседы; сохранность предложений и официального аудита; уникальность run/сообщений и ключей повторной отправки.

Повторное развёртывание пустой deanery_repro совпало с deanery_dev по колонкам, ограничениям, views, routines, индексам и триггерам. Повторный upgrade deanery_dev не изменил число строк ни одной прикладной таблицы.

Пока отсутствуют авторизация HTTP, scoped чтение по институтам/назначениям, resource API, исполнитель предложений, агент, SSE transport, OCR и подключение React. Служебные ограничения хранения не означают готовность этих функций. Следующие работы остаются по [плану](DETAILED_IMPLEMENTATION_PLAN.md), с прямым согласованием нерешённых правил.
