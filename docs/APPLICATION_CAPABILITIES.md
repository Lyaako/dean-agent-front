# Полный перечень целевых возможностей приложения

Статус11.10.2026: существующие возможности и все согласованные дополнения реализованы и прошли P00–P13. Неподтверждённые расширения исключены. Критичные правила закрыты пользователем; технические параметры записаны в журнал по его разрешению. Проверенные результаты и границы: [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md).

Основа: [подробный план](DETAILED_IMPLEMENTATION_PLAN.md), [каталог всех 56 таблиц](DATABASE_CATALOG.md), frontend `react-frontend`, SHA `9c68ae0c5f062b87811058599151bc135576b33d`, root agent SHA `d92bf5fbfc5b37c3236a6454aeffa5374fe88b11`. Перечень раскрывает этот объём, не добавляет новые экраны, инструменты или разрешения. Матрица ролей, TTL и прочие предлагаемые настройки остаются частью плана для одобрения.

Обозначения способа: **Оба** — задача доступна через агента и через существующие таблицы/формы; **Агент** — через чат с инструментами; **Интерфейс** — кнопки/формы/навигация, без команды модели; **Система** — сервер/БД/фоновые задания; **Служебно** — защищённый операторский путь без нового пользовательского экрана. Для Оба агент возвращает ответ в чат или предложение, а не автоматически нажимает кнопки и не переставляет фильтры таблицы.

Любое чтение ограничено разрешёнными строками и полями. Любая запись ограничена ролью, областью и состоянием записи. Через форму сохранение выполняется по её кнопке; через агента изменение готовится как proposal и выполняется только после отдельного решения уполномоченного сотрудника. Шесть процессов движения студента вызывают одни и те же предметные процедуры обоими способами.

Student к этим операциям доступа не получает; teacher ограничен своей оценкой/посещаемостью в назначениях и темой своей руководимой работы, как в матрице плана.

| PR12 | Сохранять историю передачи | Система + интерфейс | Кто/кому/когда/почему; прежний согласующий теряет право решения, payload/автор не меняются |
| PR13 | Подтвердить | Только интерфейс | Назначенный eligible staff, комментарий 10..2000; повторная проверка прав, срока, snapshot и правил |
| PR14 | Отклонить | Только интерфейс | Комментарий, reject и журнал; предметные данные не меняются; можно закрыть неприменимое pending |
| PR15 | Отложить рассмотрение | Интерфейс | Позже/крестик закрывает окно; pending остаётся в очереди до срока |
| PR16 | Подготовить исправленное предложение | Агент | Новое immutable proposal; заменённое становится superseded, старое не редактируется и не применяется |
| PR17 | Показывать истечение/изменившиеся данные | Интерфейс + система | Expired/stale/superseded не применяются, нужен новый запрос; передачи TTL не продлевают |
| PR18 | Показывать решение отдельно от исполнения | Интерфейс + система | Pending/approved/rejected отдельно от not_started/scheduled/running/succeeded/failed |
| PR19 | Исполнять один раз | Система | Locks/version/idempotency; повтор кнопки/окно/повтор задания не создаёт второй окончательный результат |
| PR20 | Сохранять доступ после потери чата/соединения | Интерфейс + система | Сохранённый proposal остаётся в Mine/Incoming; после обрыва/перезагрузки SSE восстанавливает тот же run по C14 |

Подтверждение/передача сообщением в чат моделью не выполняются. Eligible staff может согласовать своё обычное предложение; для коррекции оценки обязателен другой уполномоченный директор/заместитель. TTL черновика/предложения24 часа. Future approved не отменяется истечением TTL proposal. Несколько изменений — отдельные предложения.

## 16. Пять ролей по текущему проекту политики

| Роль | Чтение | Ручная запись | Агент | Решение/назначение |
|---|---|---|---|---|
| admin | Разрешённый административный контур | Действующие формы/workflows, включая непривязанных employees | Все разрешённые команды по области | Допустимые очереди, назначение/решение |
| director | Свой институт | Формы/workflows и правки привязанных сотрудников | Те же допустимые предметные действия | Управляет очередью института; для решения чужого назначения сначала назначает себе |
| dean_staff | Свой институт/деканат | Формы/workflows своей области | Разрешённые рабочие записи, формы и workflows | Взять/передать/решить назначенное себе |
| teacher | Собственные назначения, связанные студенты/работы | Основные формы read-only | Свои grade/attendance и topic руководимой работы; чтение/нормы | Только собственные отправленные предложения, без решения/назначения |
| student | Собственные данные/группа/заявки | Своя новая заявка; copies/purpose; допустимое удаление до обработки | Собственная новая заявка; чтение/нормы | Только собственные предложения и результат |

Передача не повышает права автора. На approve проверяется актуальность прав автора и согласующего. На исполнении уже подтверждённого future приказа действует авторитет приказа и повторная проверка предметных условий. Прямое саморасширение роли/области не предусмотрено.

## 18. Что остаётся за пределами текущего плана

1. Полный OLAP реализован:8 режимов, утверждённые показатели, фильтры, графики и проверка всех5 ролей по SQL controls.
2. Свободный CRUD всех 56 таблиц, редактор справочников/образовательных программ/институтов/организаций не добавляются.
3. Назначение/прекращение/отмена будущей стипендии, коррекция закрытой оценки и отмена неисполненного приказа реализованы ограниченными типизированными tools и общим DB-исполнителем, см. Q19–Q24. Новое назначение начинается сегодня или позже. Исправление ошибочного уже действовавшего назначения исключено.
4. Прямое изменение закрытой оценки, статуса/группы студента, автора/параметров подтверждаемого proposal запрещено.
5. Генерация справок/приказов/договоров в PDF, печать/электронная подпись/рассылка, CSV/Excel-экспорт не включены.
6. Новый кабинет пользователей, нормативной библиотеки или отдельная девятая вкладка очереди не включены.
7. Автономное подтверждение, передача, удаление моделью, обязательные две разные подписи и массовые атомарные пакеты не включены.
8. Синхронизация чатов, восстановление SSE после обрыва/перезагрузки и OCR всех сканированных страниц принятого PDF прямо добавлены. Средство/лимиты OCR ещё согласуются; безошибочное распознавание любого оригинала не обещается.
9. Exactly-once обычного POST ресурсов и предотвращение любого stale ручного PATCH не обещаются текущим контрактом; решение/workflow/assignment защищаются отдельно.
10. Одна общая атомарная операция ФИО + employee не обещается: текущий frontend отправляет два PATCH.

Любое расширение этого перечня, изменение предложенной политики или технический обход ограничения требует прямого подтверждения пользователя в чате перед работой.
